# flex-attendance — 자율 출근제 근태 관리

정해진 출퇴근 시각 없이 **정산기간 총 근무시간**을 맞추며 일하는
자율 출근제(선택적 근로시간제, 근기법 §52)를 지원하는 앱.

> 작업 방식은 `CLAUDE.md`. 이 프로젝트는 팀장과 함께 단계적으로 만든다.

> ## ⛔ `claude-lab/solo/` 는 절대 열어보지 말 것
>
> 같은 기획서로 클로드가 **혼자** 만든 버전이 `claude-lab/solo/flex-attendance` 에 있다.
> 팀장이 나중에 **두 결과물을 비교**한다. 한 번이라도 들여다보면 비교가 무의미해진다.
> 막혀도 보지 말고 팀장에게 물어볼 것. (`.claude/settings.json` 이 Read 를 차단한다)

## 왜 만드는가

고정 출퇴근 대신 자율 출근제를 도입하면 생기는 실제 문제를 푼다.

- 내가 이번 정산기간에 얼마나 더 일해야 하는지 감이 안 온다
- 팀원이 지금 일하는 중인지 모른다
- 관리자는 근태를 집계할 방법이 없다
- **주 52시간을 넘겼는지 아무도 제때 모른다**

## 기능

### 1. 출퇴근 체크인 / 체크아웃

- 버튼 하나로 **근무 시작 / 종료**. "지금까지 N시간", "몇 시에 종료하면 오늘 몫을 채우는지"
- **하루에 여러 번 나눠 일하기** — 오전 3h + 저녁 2h 는 **5시간**이다.
  사이 공백을 근무로 세지 않는다. 이게 계산 엔진의 핵심이다
- 사원증 CSV 와 앱 기록을 **함께** 본다. 겹치면 합쳐서 이중 계산을 막는다
- **종료를 깜빡한 날**은 사유와 함께 본인이 종료 시각을 넣는다. 이력이 남는다.
  방치된 근무가 있으면 새 근무를 시작할 수 없다

### 2. 근무시간 대시보드

- 정산기간 누적 / 소정근로 / **남은 시간** / 이 페이스면 얼마
- **일별 근무 목록** — 날짜·막대·시간·상태가 한 줄에. 눈금은 1일 소정근로
- 주 52시간 초과(정산기간 **평균** 기준), 의무근로시간대 미준수, 1일 상한 초과
- 나눠 일한 날은 "첫 시작~마지막 종료"를 근무로 읽히게 쓰지 않는다

### 3. 팀 현황 (팀장 · HR)

- **재실 요약** — 지금 근무 중 / 오프 / 종료 안 됨
- **확인 필요** — 전수 확인이 아니라 이상값만 올린다. 200명을 다 보게 하지 않는다
- **구성원별 진행률 바** + 기대선(지난 영업일 비율). 법정 한도 초과는 빨강
- 개인 상세는 본인·팀장·HR 만. **임원은 집계만** 본다

### 4. 근태 규칙 (HR)

정산기간(주/월) · 주 시작일 · 소정근로 산정 방식 · 의무근로시간대 · 선택적
근로시간대 · 휴게(§54) · 1일 상한 · 야간(§56) · 날짜 귀속 기준시각 · 공휴일.
저장하면 전 직원 집계를 원본에서 다시 계산한다.

### 5. 휴가

**본인 신청 → 팀장·HR 승인** → 승인된 것만 소정근로에서 차감.
반려는 사유 필수, 반려된 날짜는 재신청 가능.
취소는 승인 전엔 본인, 승인 후엔 승인자만.

> 잔여 연차는 관리하지 않는다. 총량을 넣으면 부여·이월·회계연도 기준이 전부
> 따라오고, 그건 휴가 관리 시스템의 영역이다.

### 6. 근태 파일 반영 (HR)

벤더 독립 컬럼 매핑, BOM·CRLF·따옴표 처리, 중복 태그 제외,
**배치 단위 무효화**(잘못 올린 파일을 되돌린다).

### 7. 마감

유예 3일 뒤 자동 마감 → **사람별 스냅샷 동결** → 늦게 온 태그가 들어오면
**"마감 후 값이 바뀌었습니다"** 로 드러낸다. 재마감은 HR 만, 사유 필수.

> 임포트를 막지 않는 이유: 원본은 append-only 여야 하고 막으면 데이터가 유실된다.
> 대신 공식 기록은 스냅샷을 쓰고 차이를 눈에 보이게 만든다.

### 8. 알림 · 전사 집계 · 사용자 관리

읽음 개념 없이 **"확인할 항목"** — 해결하면 저절로 사라진다.
전사/팀별 집계 + CSV 내보내기. 사용자·팀·역할 관리.

## 설계에서 정한 것

| 문제 | 정한 것 |
|---|---|
| 자정 넘긴 근무 | 기준시각(기본 05:00) 이전은 전날로 귀속 |
| 타임존 | 저장은 UTC, 판정·표시는 조직 타임존. 시계는 `lib/clock.ts` 하나 |
| 체크아웃 누락 | 0분으로 두지 않고 **평소 패턴 추정치를 미리 채워준다** |
| 검토 기준 | 보정 **횟수**가 아니라 **기대값에서 벗어난 정도** |
| 주 52시간 | 개별 주가 아니라 **정산기간 평균**으로 판정 (§52) |
| 휴게 | 법정 기준은 근로시간이지만 순환이라 체류시간을 대리 지표로 |

**정직한 신고가 손해가 되지 않게** 하는 것을 반복해서 고쳤다 —
반차 쓰고 일한 날, 외근이 잦은 사람, 사원증을 깜빡한 사람이
정직할수록 의심받는 구조를 네 번 만들었다가 걷어냈다.
(배경은 `lib/attendance/settle.ts` 상단)

## 기술

Next.js 16 (App Router) · React 19 · Postgres 17 · Drizzle · Luxon · Vitest

- **JS 없이도 근태 입력이 된다.** 폼은 서버 컴포넌트, 결과는 쿼리 파라미터로
- 도메인 계층(`lib/attendance/*`)은 DB 를 모른다. 순수 함수 + 단위 테스트
- 원본(`attendance_logs`)은 append-only, 집계(`work_days`)는 언제든 재계산
- 동시 요청은 `pg_advisory_xact_lock` 으로 사람별 직렬화

**규모 실측**: 16,000행 임포트 + 200명 재계산 **4.7초** · `/team` 473ms

**규율을 기계가 강제한다** — 시계 단일화, 표 가로 스크롤, 위험 버튼 확인 단계,
액션 오류 기록, 인코딩 손상. 전부 `*.guard.test.ts` 가 잡는다.

## 운영

### 처음 도입할 때

`db:seed` 는 **데모 데이터**다. 실제 회사에 쓰면 안 된다.

```
npm run db:bootstrap -- "회사명" "팀명" <사번> "이름"
```

조직 하나 · 팀 하나 · 첫 HR 한 명만 만든다. 그다음 순서가 중요하다 —
**근태 규칙을 CSV 보다 먼저 맞춘다.** 기본값은 예시일 뿐이고,
의무근로시간대·휴게·상한은 **서면합의 사항**이다.
순서를 바꿔도 되돌릴 수는 있지만 한 번 본 숫자가 나중에 전부 바뀐다.
(근태 설정 화면 상단에 순서가 있다)

### 백업

```
npm run db:dump        backups/ 에 타임스탬프 덤프 (저장소에 안 올라간다)
```

`db:reset:force` 는 **볼륨까지 지운다.** 개발용이고 이름에 force 가 붙은
이유다. 실행 전에 반드시 `db:dump` 를 먼저 돌린다.

### 비밀번호를 잃었을 때

HR 은 사용자 관리에서 초기화해준다. **HR 자신이 잠기면** 서버에서:

```
npm run db:reset-password -- <사번>
```

셀프서비스 재설정 화면은 없다. 메일 발송 수단이 없고, 그런 화면은 드문
상황을 위해 상시 공격면을 여는 셈이 된다. 서버 접근 권한이 곧 인증이다.

### 마감과 알림

**배치 없이 돌아간다** — 화면을 열거나 기록을 쓸 때 함께 정리된다.
예측 가능한 시각에 마감하고 싶으면 cron 을 얹는다.

```
npm run db:close-periods    유예 지난 기간 마감 + 오래된 열람 이력 파기
npm run db:notify           알림 재계산
```

### 개인정보

- 열람 이력은 **180일** 뒤 파기 (조직 설정으로 조정)
- 로그인 시도 IP 는 24시간 뒤 파기
- 오류 기록은 **외부로 보내지 않는다.** 스택트레이스도 저장하지 않는다 —
  사번·이름이 섞여 나가는 통로가 된다. 30일 뒤 삭제
- 보안 헤더 5개 (HSTS · nosniff · DENY · Referrer · Permissions)

## 아직 없는 것

- **CSP** — Next 가 RSC 페이로드를 인라인 스크립트로 심어서 nonce 방식이 필요하다.
  `unsafe-inline` 은 있는 척하는 보안이라 넣지 않았다
- **cron** — lazy 방아쇠로 대체 중. 배포 형태를 정한 뒤 얹는다
- **이월 정책** — 정산기간 초과·부족분. 연장근로 수당은 그 기간에 지급해야
  하므로 코드보다 노무 검토가 먼저다
- **SSO** — 자리(`externalId`, nullable `passwordHash`)만 있다. 사내 IdP 없이는 실측 불가
- **주 52시간 사전 경고** — 지금은 이미 넘긴 뒤에 알린다.
  "이 페이스면 목요일에 넘습니다"로 바꾸는 것이 남은 가장 큰 값
- **마감이 판정까지 지키지는 않는다** — 스냅샷에 6개 숫자만 얼린다.
  규칙을 바꾸면 마감된 기간의 위반 판정은 다시 계산된다.
  규칙 변경이 2년에 한 번 수준이라 우선순위에서 뺐다
