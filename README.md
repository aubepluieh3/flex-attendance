# flex-attendance — 자율 출근제 앱 (협업 버전)

직원이 정해진 출퇴근 시각 없이, **월/주 단위 총 근무시간**을 스스로 관리하며 일하는
자율 출근제(Flexible Work) 를 지원하는 앱.

> 이 프로젝트는 **사용자와 함께 단계적으로** 만든다. 작업 방식은 `CLAUDE.md` 참고.
> 같은 아이디어를 클로드가 혼자 만든 버전이 `claude-lab/solo/flex-attendance` 에 있다.
> 막힐 때 참고할 수는 있지만, **먼저 보고 베끼지 말 것.** 설계는 사용자와 처음부터 정한다.

## 왜 만드는가

고정 출퇴근 대신 자율 출근제를 도입하면 생기는 실제 문제들을 푼다.

- 내가 이번 달에 얼마나 더 일해야 하는지 감이 안 온다
- 팀원이 지금 일하는 중인지 아닌지 모른다
- 관리자는 근태를 집계할 방법이 없다

## 핵심 기능

### 1. 출퇴근 체크인/체크아웃
- 버튼 하나로 근무 시작 / 종료
- 하루에 여러 번 나눠서 일하는 경우(오전 3h + 저녁 2h) 지원
- 체크아웃을 깜빡한 경우 나중에 수정 가능 (수정 이력 남김)

### 2. 근무시간 대시보드
- 이번 주 / 이번 달 누적 근무시간
- 목표 대비 남은 시간 (예: 월 소정근로 160h 중 112h 완료, 48h 남음)
- 지금 페이스대로면 월말에 몇 시간이 될지 예상치
- 일별 근무시간 그래프

### 3. 팀 현황
- 팀원별 현재 상태 (근무 중 / 오프)
- 팀원별 이번 달 진행률
- 개인 상세 기록은 본인과 관리자만

### 4. 근태 규칙
- 월 소정근로시간 설정
- 1일 최대 근무시간 상한 (예: 12h) 초과 시 경고
- 휴가/반차 등록 → 소정근로시간에서 자동 차감

### 5. 관리자 기능
- 팀 전체 월간 집계 조회
- CSV 내보내기

## 같이 이야기하며 정할 것

코드보다 먼저 이야기가 필요한 지점들. 선택지만 늘어놓지 말고,
**내 생각을 먼저 말하고 걸리는 부분을 드러내면서** 같이 결론을 찾는다.

1. 기술 스택 (서버 / 클라이언트 / DB)
2. 어디까지 만들 것인가 — 5개 기능 전부인지, 1~2번만 제대로인지
3. 인증 방식 (사내 SSO / 자체 로그인 / 데모용 계정 선택)
4. 배포 형태 (웹 / 모바일 / 데스크톱)
5. **시간 처리 규칙** — 은근히 어려운 부분이다. 자정 넘긴 근무를 어느 날로 칠지,
   타임존을 어디에 고정할지, 체크아웃 안 하고 퇴근한 기록을 어떻게 다룰지.
   여기서 잘못 정하면 나중에 집계가 전부 흔들린다

## 시작하기

이 프로젝트는 비어 있다. 먼저 사용자가 이걸 어떤 맥락에서 쓰려는 건지
(실제 회사에 도입? 연습용?) 물어보는 것부터 시작하면 좋다. 거기에 따라 위 결정들이
전부 달라진다.
